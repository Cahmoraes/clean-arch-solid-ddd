# Quando usar SDD (Spec-Driven Development)
Produzir um "entregável". Algo que faz diferença para o cliente em termos de valor de negócio e não o pedaço de uma tarefa.
Não é um software completo; mas uma parte que entrega valor.

Quero suportar um novo gateway de pagamentos
Quero realizar uma integração com um sistema de emissão de notas fiscais
Quero migrar um projeto de uma tecnologia X para Y


## Quando não utilizar
Não utilizar para otimizar uma query lenta
Não utilizar para alterar uma regra de negócio
Não utilizar para investigar e resolver bugs
Não utilizar para elevar cobertura de testes

# Heurística de boas práticas
O que não for especificado não será feito
- Possui testes de componentes? Se sim, precisa de uma task que informe isso.
- Cria layout a partir do Figma? Se sim, precisa de uma task que informe isso.
